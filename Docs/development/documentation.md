# Writing documentation

Documentation lives next to the code it describes and is published as one site.

## Where things go

| Content | Location | Format |
|---|---|---|
| User manual | `Packages/com.xra.quadbuffer/Documentation~/` | Markdown. Ships inside the package, where Unity expects package docs. |
| C# API reference | XML doc comments (`///`) in package source | Generated by DocFX. |
| Native API reference | Doxygen comments (`/** */`) in `NativePlugin/include` and `src` | Generated by Doxygen. |
| Architecture | `Docs/architecture/` | Markdown with Mermaid diagrams. |
| Decisions | `Docs/adr/` | One Markdown file per decision. |
| Release notes | `Packages/com.xra.quadbuffer/CHANGELOG.md` | [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). |

## Conventions

- Every public C# type and member gets a `<summary>`. Internal types are documented when
  their behavior is not obvious; DocFX does not publish them.
- Every function in the native public header gets `@brief`, `@param` and `@return`.
  Doxygen warns on anything undocumented.
- Write the manual for someone using the package, not someone changing it.
- Record a decision in an ADR when it is hard to reverse or someone would reasonably ask why.
  Copy `adr/template.md`, number it sequentially, and add it to `adr/toc.yml`.

## Building the site

```powershell
./Docs/build-docs.ps1            # build into Docs/_site
./Docs/build-docs.ps1 -Serve     # build and serve at http://localhost:8080
```

The script:

1. Reads the package version from `package.json`.
2. Copies the Unity assemblies into `Docs/_unityrefs`; `Docs/api-project` compiles the package code against them
   (and .NET Standard 2.1) so DocFX can read the C# API.
3. Runs Doxygen into `Docs/native`.
4. Copies the user manual and `CHANGELOG.md` into `Docs/manual` (DocFX only resolves links inside `Docs/`).
5. Restores DocFX as a local .NET tool (pinned in `.config/dotnet-tools.json`) and builds the site.

`Docs/_site`, `Docs/obj`, `Docs/_unityrefs`, `Docs/native`, `Docs/manual`, `Docs/api-project/bin`, `Docs/api-project/obj` and
generated `Docs/api/*.yml` are build output and are not committed. Edit the manual in the package,
not in `Docs/manual`.
